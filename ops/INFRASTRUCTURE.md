# FreeAppStore Infrastructure

Private documentation for AI agents and maintainers. Covers how publishing, DNS, and deployments work.

## App Types

Apps on the platform fall into two categories:

### 1. Standalone Apps (no backend)

Pure client-side apps. No accounts, no server, all data in localStorage. Examples: chess, quiz, puzzle, math, books.

- Frontend only (React + Vite → Cloudflare Pages)
- Zero backend infrastructure
- User data stays on device
- No account required

### 2. Connected Apps (platform SDK)

Apps that need auth, per-user storage, realtime, or third-party API proxying use `@freeappstore/sdk`. The backend is the platform API at `api.freeappstore.online`, powered by `freeappstore-online/platform` (Cloudflare Workers + D1 + Durable Objects).

```
+---------------------+     +-------------------------+
| App Frontend        |---->| api.freeappstore.online  |
| (CF Pages)          |     |                         |
| + @freeappstore/sdk |     | - GitHub OAuth          |
|                     |     | - Per-user KV (D1)      |
|                     |     | - Realtime rooms (DO)   |
|                     |     | - Secret-injecting proxy|
+---------------------+     +-------------------------+
```

### SDK features

```ts
import { initApp } from '@freeappstore/sdk';
const fas = initApp({ appId: 'my-app' });

// Auth (GitHub OAuth)
await fas.auth.init();
fas.auth.signIn();

// Per-user KV (scoped to appId + userId)
await fas.kv.set('theme', { color: 'plum' });
const theme = await fas.kv.get<{ color: string }>('theme');

// Realtime rooms (WebSocket fan-out)
const room = fas.rooms.join('lobby');
room.onMessage((msg) => console.log(msg));

// Third-party API proxy (keys never touch the browser)
const res = await fas.proxy.fetch('api.openweathermap.org/data/2.5/weather?q=London');
```

Limits: 1MB KV per user, 100 keys, 64KB per value, 32 peers per room, 4KB per message.

## Hosting: Path B (current — since 2026-05-21)

**Every app's static build is served from a single Cloudflare Worker
(`freeappstore-host`) reading from one R2 bucket (`fas-apps`).** Replaces
the per-app CF Pages project model — see the next section for what came
before.

```
GitHub (freeappstore-online/<app>)     R2: fas-apps                Single Worker          Subdomain
┌──────────────────────┐               ┌─────────────────┐         ┌─────────────────┐    ┌──────────────────────────┐
│ <app> repo           │──push──────▶  │ apps/<app>/*    │ ◀────── │ freeappstore-   │ ──▶│ <app>.freeappstore.online│
│ + deploy.yml         │   GH Action   │ index.html      │  D1     │ host worker     │    │ (wildcard DNS + SSL)     │
└──────────────────────┘   builds +    │ assets/...      │  routes │ on *.zone/*     │    └──────────────────────────┘
                           uploads     └─────────────────┘  table  └─────────────────┘
```

Key consequences:
- **No 100-projects-per-account cap** — apps scale into the thousands+.
- **Centralized headers/CSP** — emitted from the host Worker, not
  per-app `_headers`. Apps no longer ship their own header policy.
- **Subdomain → R2 prefix** mapping lives in the `fas` D1 database's
  `routes` table (one row per app).
- **Build still runs in GitHub Actions** (`.github/workflows/deploy.yml`
  in each app repo), uploads via R2's S3 API.
- **Per-app URL unchanged** — `kanban.freeappstore.online` continues to
  work, just served differently.

Sibling components:
- `fas/host/` — the host Worker (one file: `src/index.ts`)
- `fas/host/migrations/0001_create_routes.sql` — D1 schema
- `fas/templates/template-*/.github/workflows/deploy.yml` — build + upload
- `fas/admin/src/publish.ts insertHostRoute()` — the publish step that
  inserts the D1 row

Secrets: see [workspace SECRETS.md](../../SECRETS.md). Runbooks for Path
B failures live at [workspace RUNBOOKS/](../../RUNBOOKS/).

Pro apps (PAS/PGS) are **still on the legacy CF Pages model** described
below — they're heavier and few in number, and per-project isolation is
worth more than scale for them. The current trigger to migrate Pro is
"when `proappstore-online` hits 50 CF Pages projects, design WfP."

## Storefront URL structure

The freeappstore.online storefront is generated by `build.js` at build
time from the registry. Stable URL shape:

| URL | What | Source |
|---|---|---|
| `/` | Home grid (all apps, search, AI mode) | `templates/index.html` |
| `/apps/<slug>.html` | Per-app detail page (iframe preview, metadata, history, ratings, author chip) | `templates/app-detail.html` |
| `/u/<github-username>.html` | Per-author profile page — avatar, app count, earned badges, app grid | `templates/author.html` (added 2026-05-21) |
| `/quality/<slug>/` | Per-app code-quality report | quality-scan pipeline |
| `/about`, `/pricing`, `/get-started`, etc. | Static content | top-level `*.html` files in repo |

### Authors + badges (added 2026-05-21)

Each app's `creatorGithub` field in `registry.json` populates the author
chip on its detail page and gets a profile page generated at
`/u/<github-username>.html`. The admin Worker's `/v1/publish` already
collects `creatorGithub` (was previously used only to grant repo push
access); the storefront's `build.js` reads it to:

1. Compute the set of unique creators across the registry.
2. For each, emit one `/u/<username>.html` using `templates/author.html`,
   with avatar pulled from `avatars.githubusercontent.com` (already in
   the CSP img-src allowlist) and the author's full app grid.
3. Compute earned badges from registry data — `computeAuthorBadges()` in
   `build.js`. Pure function: app count + distinct categories +
   `qualityScores` + `auditMap`. No DB schema, no per-author state.
4. Render the chip on every app's detail page (`{{AUTHOR_CHIP}}` token
   in `templates/app-detail.html`).

Adding a new badge rule = pushing one `{icon, label, title}` object
into `computeAuthorBadges()`. Renderer + CSS auto-style it. Tooltip
comes from `title`. See `~/dev/stores/fas/freeappstore/build.js` for
the current rule set.

## Hosting: legacy CF Pages model (pre-2026-05-21)

This section describes the pre-Path-B model that PAS/PGS still use. FAS
ran on it until the 100-projects cap forced the redesign.

**Apps are statically hosted on Cloudflare Pages, one project per app.**
The stack:
- Frontend: Static React SPA → Cloudflare Pages (global CDN)
- Backend (if needed): `@freeappstore/sdk` → `api.freeappstore.online` (platform-managed Workers + D1 + DO)

Apps that need a backend use the platform SDK. The frontend is always a
static build deployed to CF Pages.

## Deployment Philosophy

**ONE environment only. Production. That's it.**

- No dev/staging/preview environments
- Push to `main` = deploy to production
- No rollbacks — code only moves forward
- If something breaks, fix it and push a new commit
- No feature flags, no gradual rollouts
- Developers fix issues in prod and patch forward

This keeps things simple. Every app has one URL, one branch, one truth.

## Environment Variables

**Deployment config is NEVER in the repo.** All env vars live in CF Pages project settings.

### For standalone apps:
- `NODE_VERSION`: 22 (set on all projects)
- No other env vars needed

### For connected apps (using `@freeappstore/sdk`):
- `NODE_VERSION`: 22
- No additional env vars needed — the SDK talks to `api.freeappstore.online` by default

### Developer workflow:
- `npm i @freeappstore/sdk` in the app's web package
- Call `initApp({ appId: 'my-app' })` — auth, KV, rooms, and proxy are available immediately
- `.env.production` files must NOT be committed to repos

## Template Repos

Developers bootstrap new apps from these templates:

- **freeappstore-online/template-standalone** — For apps with no backend (localStorage only)
- For connected apps (auth, KV, rooms, proxy): add `@freeappstore/sdk` to a standalone template

Templates include:
- Correct pnpm workspace structure
- Brand CSS variables and fonts
- Responsive Shell component (sidebar + dock)
- CI workflow (typecheck on PRs)
- CLAUDE.md for AI agent instructions
- PWA manifest
- .gitignore

To start a new app:
```bash
gh repo create freeappstore-online/appname --template freeappstore-online/template-standalone --public
# then find-and-replace APPNAME with your app name
```

## Cloudflare Account

Account credentials, zone IDs, and the admin email are not committed to this repo. Look them up in the CF dashboard or the platform admin's secret store.

- **Auth method for API**: Global API Key (X-Auth-Email + X-Auth-Key headers)
- **Auth method for wrangler CLI**: OAuth token (auto-refreshes, stored at `~/Library/Preferences/.wrangler/config/default.toml`)

### OAuth token limitations

The wrangler OAuth token does NOT have DNS write permission. There is no `zone:write` scope available in wrangler's OAuth flow. DNS modifications require the Global API Key.

## How to Add a New App

> **Historical reference only.** The current workflow is **freeappstore.online/app/** (creators) or the admin API (maintainers). The recipes below remain documented for emergency manual recovery only — e.g. portal outage. Do not run them as the normal path; see [`SKILLS.md`](./SKILLS.md) for the rules AI agents and creators should follow.

### 1. Create the repo

```bash
gh repo create freeappstore-online/appname --public
```

### 2. Create CF Pages project (via API)

```bash
# Refresh token first
wrangler whoami
CF_TOKEN=$(grep oauth_token ~/Library/Preferences/.wrangler/config/default.toml | cut -d'"' -f2)
ACCT="<CF_ACCOUNT_ID>"

curl -s -X POST "https://api.cloudflare.com/client/v4/accounts/$ACCT/pages/projects" \
  -H "Authorization: Bearer $CF_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "name": "freeappnameapp",
    "source": {
      "type": "github",
      "config": {
        "owner": "freeappstore-online",
        "repo_name": "appname",
        "production_branch": "main",
        "deployments_enabled": true
      }
    },
    "build_config": {
      "build_command": "pnpm install && pnpm build",
      "destination_dir": "web/dist"
    },
    "deployment_configs": {
      "production": {
        "env_vars": {
          "NODE_VERSION": {"value": "22"}
        }
      }
    }
  }'
```

### 3. Add custom domain to Pages project

```bash
curl -s -X POST "https://api.cloudflare.com/client/v4/accounts/$ACCT/pages/projects/freeappnameapp/domains" \
  -H "Authorization: Bearer $CF_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"name":"appname.freeappstore.online"}'
```

### 4. Add DNS CNAME record (requires Global API Key)

```bash
ZONE="<freeappstore-zone-id>"
EMAIL="<CF_ADMIN_EMAIL>"
KEY="<GLOBAL_API_KEY>"

curl -s -X POST "https://api.cloudflare.com/client/v4/zones/$ZONE/dns_records" \
  -H "X-Auth-Email: $EMAIL" \
  -H "X-Auth-Key: $KEY" \
  -H "Content-Type: application/json" \
  --data '{"type":"CNAME","name":"appname","content":"freeappnameapp.pages.dev","proxied":true}'
```

### 5. Add app card to landing page

Edit `~/dev/freeappstore/index.html` — add a new `.app-card` in the `.apps-grid`.

### 6. Push and verify

Push both the app repo (triggers CF Pages build) and the freeappstore repo (updates landing page).

## How Deployment Works

1. Developer pushes to `main` branch on GitHub
2. Cloudflare Pages GitHub app detects the push
3. CF Pages clones the repo, runs `pnpm install && pnpm build`
4. Built output from `web/dist` is deployed to the global CDN
5. Available at `projectname.pages.dev` and any custom domains

No GitHub Actions needed. No tokens or secrets in repos. CF Pages handles everything directly.

## Troubleshooting

### Build fails on CF Pages

- **"Cannot find type definition file for 'node'"** — Add `@types/node` to devDependencies
- **pnpm version mismatch** — Ensure `packageManager` field in root package.json matches lockfile
- **"Ignored build scripts: esbuild"** — Add `"pnpm": {"onlyBuiltDependencies": ["esbuild"]}` to root package.json

### Custom domain stuck on "pending"

1. Verify CNAME record exists in the zone (use API with Global Key to check)
2. Delete and re-add the custom domain on the Pages project
3. Wait 2-5 minutes for SSL certificate provisioning

### OAuth token expired

Run `wrangler whoami` — it auto-refreshes the token. Then re-read from `~/Library/Preferences/.wrangler/config/default.toml`.
