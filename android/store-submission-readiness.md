## Android data inventory and proposed form mapping

Google's [Data safety definitions](https://support.google.com/googleplay/android-developer/answer/10787469) cover data sent off-device, including pseudonymous identifiers and optional features. They differ from Apple's categories and purposes. The rows below derive from Android code and the shared backend, not from an Apple-label copy. Collection is not ephemeral: account rows, job records and location queues persist. Optional authenticated features can be avoided while using Store; do not describe that as no collection.

| Proposed Google type | Actual flow and purpose |
| --- | --- |
| Personal info: Name, Email address, User IDs | Account authentication/profile and device association. `CompanionRepository.kt`, backend `routes/native.ts` `/me`, `routes/auth.ts`. App functionality and account management. The app does not require a phone number or postal address. |
| Device or other IDs | Native-device ID/credential and account-linked runner; stable hashed-IP pairing identifier with UTC-day counter. Device connection, security and abuse prevention. No advertising identifier. `FasApi.kt`, backend `native-auth.ts`, `native-companion.ts`. |
| Precise location | `LocationService.kt` → `CompanionRepository.sync` uploads coordinates, accuracy and timestamp only after per-app consent and Android fine/background permissions. App functionality. Approximate-only permission does not start this collector; do not infer approximate-location collection from the manifest's coarse permission alone. Check any infrastructure IP geolocation separately. |
| Audio files: Other audio files | On-device synthesized narration uploaded with sentence timings under the connected account. `Generation.kt`, `Kokoro.kt`, generation result endpoint. App functionality. This is not microphone recording, music-library access or a user's recorded voice. |
| App activity: Other user-generated content | Optional quality-report note and submitted review content in `GenerationApi.report`; the selected app's publisher can see it. App functionality. |
| App activity: App interactions | Account-linked job claims, uploads, quality choices, outcomes and device last-seen activity. App functionality; operational analytics when used to inspect usage or job health. Catalogue search, favourites and recents stay on-device. |
| App info and performance: Diagnostics | Attempt error class/message, stage duration, CPU, memory, battery/charging, network, thermal state, app/OS/device version and execution context. `AttemptProbes.kt`, `Generation.kt` `Attempt.json`, backend generation events. App functionality and Analytics: Google's definition includes diagnosing bugs and monitoring app health even without an analytics SDK. No crash-reporting SDK or uploaded crash stack was found. |

**Actual recipients matter.** App publishers can be third parties, not merely service providers: generation owner endpoints expose contributor user ID/login, reports and attempt records. Prepare **Shared** for those identifiers, report content, interactions and diagnostics; do not claim “no sharing” solely because the first upload goes to FreeAppStore. Accepted audio is publicly available. User-selected location recipient apps and explicit Share record exports also transfer data. Google's user-initiated/consented-transfer exception may apply to a particular flow; do not apply it to unrelated publisher-visible diagnostics by assumption. Reconcile recipient ownership and actual disclosure before final form submission.

**Not collected by these native features:** QR camera frames remain local; no microphone permission; no contacts/calendar/SMS/installed-app inventory; local catalogue search/favourites/recents are not uploaded history. External browser apps have their own data behavior. Android uses native location APIs, a locally rendered route map, CameraX/ZXing and offline Sherpa inference; no advertising, analytics or crash-reporting SDK appears in `app/build.gradle.kts`. This dependency observation does not negate the explicit backend telemetry above.

**Security and deletion:** native API uses fixed-origin HTTPS with redirects refused, and the manifest disables cleartext traffic and Android backup. Existing model downloads verify a pinned hash. The app's signed-in Settings includes **Delete account**, opening `https://freeappstore.online/app/settings?delete-account=1`. The public [deletion resource](https://freeappstore.online/delete-account) was fetched successfully and names the companion, describes the web path, support fallback and retained records. This supports an available deletion-request path; no real account was deleted during verification. Sign out only revokes the device and is not account deletion. Do not claim an independent MASA/security-lab badge from the repository audit.

Retention and linked-data details: [device data inventory](../docs/device-data.md), [native companion lifecycle](../docs/native-companion.md), [privacy policy](https://freeappstore.online/privacy). Active location rows expire after seven days and generation attempts after fourteen days, with a cleanup job every fifteen minutes; managed database recovery history can retain older copies for up to thirty days depending on plan; submissions/reports last until account or app removal. Accepted narration can remain public without the contributor after account deletion, while publisher blocks/audit entries can retain the user ID until app removal. Do not promise every record is erased immediately.
